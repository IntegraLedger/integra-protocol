**LCP profile `x402/request-commitment`: the request an x402 challenge answers, in the ATR's binding slot.**

1. The ATR's `x402` binding slot holds `{accepts, request}`: every option the challenge offers, exactly as issued, and the commitment to the request the challenge answers. Anyone who holds the ATR and the request reproduces the commitment by the rule for its transport, and so H.
2. **HTTP.** The commitment is `{method, path, query, bodyDigest}`: the request's method token as received; its request-target, which starts with `/` and holds visible ASCII alone, split at its first `?` into `path`, before it, and `query`, after it, `""` where it holds no `?`; and `bodyDigest`, SHA-256 over the body's bytes exactly as received, as `0x` lowercase hex. Nothing is normalised: no percent-decoding, no reordering of the query, no change to the method's case. A request that is not an object, a method or target that is not a string, a method that is not a token (RFC 9110, sections 9.1 and 5.6.2: one or more of the visible ASCII characters other than the delimiters `"(),/:;<=>?@[\]{}`), a body that is not bytes, or a target that does not start with `/` or holds a character outside visible ASCII is refused `x402/request-target-invalid`; a target over 8192 characters, or a body over 1 MiB, is refused `x402/request-too-large`.
3. **HTTP header fields.** A resource server may name request header fields its price or its answer rests on. Where it names one or more, the HTTP commitment also holds `headers`: for each field named, in the order named, `{name, digest}`, `name` the field's name lower-cased and `digest` SHA-256 over the field's value as received, as `0x` lowercase hex, never the value. The value is that of the field's lines, each as HTTP parses it, without its leading and trailing spaces and tabs and with nothing else normalised (RFC 9110, section 5.5); the lines of a field received more than once are joined in the order received by a comma and a space (RFC 9110, section 5.3), and those of `cookie` by a semicolon and a space, as HTTP/2 joins them (RFC 9113, section 8.2.3). A field the request lacks has `digest` `null`, so an absent field differs from an empty one, whose digest is that of no bytes. A named field is a field name (RFC 9110, section 5.1), compared lower-cased, and is named once. A value holding a character outside visible ASCII, the space and the tab is refused `x402/request-header-invalid`, and a value over 1 MiB, its lines joined, `x402/request-too-large`. Fields named with no header fields given are refused `x402/request-header-invalid`, so that a commitment never holds `null` for a field nobody read, as are names that are not a list of distinct field names, header fields that are not a record of strings or lists of strings, and two keys of that record that name one named field, whose order is not known. Only the named fields are read. With no field named the commitment has no `headers` member and is the four members of rule 2 alone. A paid request whose named fields' values differ answers another commitment. The cost, stated: whoever holds the ATR reads each named field's name and digest, and a digest of a short or common value, a tier, a language or a country, is guessed by hashing the candidates, so the commitment hides only a value that cannot be guessed. A resource server names no field that a proxy between it and the client writes or changes, since the paid retry's value then differs from the one committed.
4. **MCP.** An x402 challenge over MCP answers a `tools/call` request (x402's MCP transport). The commitment is `{tool, argumentsDigest}`: `tool` is the request's `params.name` exactly as received, a well-formed string of 1 to 8192 characters; `argumentsDigest` is SHA-256 over the UTF-8 of the RFC 8785 form of `params.arguments`, as `0x` lowercase hex, where `arguments` absent is read as `{}`. A call that is not an object, a `name` that is not such a string, or `arguments` that are present and not a JSON object, `null` among them, is refused `x402/tool-call-malformed`, and arguments whose RFC 8785 form is over 1 MiB `x402/request-too-large`.
5. Over MCP nothing else of the request is committed. `params._meta` is not: the client retries the same tool call with its payment in `_meta["x402/payment"]`, as x402's MCP transport has it and as `@x402/mcp` 2.30.0's client does (`src/client/x402MCPClient.ts:562-580`, the first call `{name, arguments: args}`, `args` being `{}` where the caller gives none; `:684-707`, the retry `{name, arguments: args, _meta}`), and `_meta` may carry other members a client sets per call. The JSON-RPC `id` and envelope are not committed either. A retried call therefore has the commitment of the first, and a call to another tool, or with any argument changed, has another.
6. The resource server computes the commitment from the request it answers, with the header fields it names, ties it into the ATR with the options at issue, and serves a paid retry only where the retry's commitment equals the one the ATR holds.
7. The vectors are `x402-request-commitment.json`: each commitment over HTTP, with and without named header fields, and over MCP, and each refusal with one member of a good request or call changed. Their oracles are Python's `hashlib` for the digests, a `node:http` server that joins a field's lines for the header values, and `canonicalize` 5.1.0, an RFC 8785 implementation of its own, for the arguments' form.
