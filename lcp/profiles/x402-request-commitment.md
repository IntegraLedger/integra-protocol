**LCP profile `x402` request commitment: the request an x402 challenge answers, in the ATR's binding slot.**

1. The ATR's `x402` binding slot holds `{accepts, request}`: every option the challenge offers, exactly as issued, and the commitment to the request the challenge answers. Anyone who holds the ATR and the request reproduces the commitment by the rule for its transport, and so H.
2. **HTTP.** The commitment is `{method, path, query, bodyDigest}`: the request's method token as received; its request-target, which starts with `/` and holds visible ASCII alone, split at its first `?` into `path`, before it, and `query`, after it, `""` where it holds no `?`; and `bodyDigest`, SHA-256 over the body's bytes exactly as received, as `0x` lowercase hex. Nothing is normalised: no percent-decoding, no reordering of the query, no change to the method's case. A target over 8192 characters, or a body over 1 MiB, is refused.
3. **MCP.** An x402 challenge over MCP answers a `tools/call` request (x402's MCP transport). The commitment is `{tool, argumentsDigest}`: `tool` is the request's `params.name` exactly as received, a well-formed string of 1 to 8192 characters; `argumentsDigest` is SHA-256 over the UTF-8 of the RFC 8785 form of `params.arguments`, as `0x` lowercase hex, where `arguments` absent is read as `{}`. `arguments` that are not a JSON object are refused, and so are arguments whose RFC 8785 form is over 1 MiB.
4. Over MCP nothing else of the request is committed. `params._meta` is not: the client retries the same tool call with its payment in `_meta["x402/payment"]`, as x402's MCP transport has it and as `@x402/mcp` 2.30.0's client does (`src/client/x402MCPClient.ts`, the retry's `{name, arguments: args, _meta}`), and `_meta` may carry other members a client sets per call. The JSON-RPC `id` and envelope are not committed either. A retried call therefore has the commitment of the first, and a call to another tool, or with any argument changed, has another.
5. The resource server computes the commitment from the request it answers, ties it into the ATR with the options at issue, and serves a paid retry only where the retry's commitment equals the one the ATR holds.
6. The vectors are `x402-request-commitment.json`.
