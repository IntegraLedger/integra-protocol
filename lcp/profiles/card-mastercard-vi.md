**LCP profile `card/mastercard-vi`: the ATR hash in a Verifiable Intent checkout.** This profile targets Verifiable Intent at commit `356c296` of `agent-intent/verifiable-intent` (2026-04-20): its credential format (`spec/credential-format.md`, cited `§`) and its Python reference SDK (`src/verifiable_intent/`).

1. The `checkout_jwt` payload has the member `"legalContext":{"type":"sha256","value":H,"legalContextUrl":L}`, with `legalContextAgreementUrl` after the link where an agreement URL is given. Where the merchant writes the `checkout_jwt`, it writes the member. In Immediate mode the specification lets the agent create the `checkout_jwt` (§6.3): the merchant then shows `{"legalContext":…}` as `card/visa-tap` rule 1 states it, and lcp's `read` takes that object as it takes a `checkout_jwt`; lcp's `build`, given the checkout payload the agent creates, writes the member into it and returns it for the agent to sign as its `checkout_jwt`.
2. The wallet or agent fetches L, hashes what it receives and compares with H as 32 decoded bytes; on a mismatch it does not sign.
3. On a match the user's L2 (Immediate) or the agent's L3b (Autonomous) checkout mandate carries that `checkout_jwt` with `checkout_hash` = BASE64URL(SHA-256(ASCII(checkout_jwt))), and a payment mandate's `transaction_id` equals it (§6.2).
4. Immediate presents `l2`, the user's L2, whose header `typ` is `kb-sd-jwt` (§4.2). A full Autonomous L2, whose `typ` is `kb-sd-jwt+kb`, presented under Immediate is refused `card/vi-typ`.
5. Autonomous presents `l1`, `l2` and `l3b`, where `l2` is, byte for byte, the merchant's view of the user's L2 that §5.4 defines, `L2_base_jwt~checkout_disclosure~item_disclosure~`: the presentation L3b's `sd_hash` covers. Any other view is refused `card/vi-sd-hash-mismatch`, the reference SDK example's role view among them, which carries the checkout mandate with every acceptable item in the L2's order (`examples/helpers.py:233-273`; `examples/autonomous_flow.py:281-283`).
6. lcp verifies, in Autonomous mode, L3b's signature under the key L2's open checkout mandate delegates and L2's under L1's `cnf.jwk`, each over the bytes received; it does not verify L1's issuer signature, and in Immediate mode it verifies no signature.
7. The signer's rule. The reference SDK verifies each signature over its own re-encoding of the parsed JSON (`src/verifiable_intent/crypto/sd_jwt.py:117-118`), so a layer signed over other bytes passes lcp's check and fails a verifier built like it. A signer therefore signs JSON that is compact, with every non-ASCII character escaped as `\uXXXX` and members in insertion order, as Python's `json.dumps(…, separators=(",", ":"))` writes it.
8. The offer's lifetime. The layer the buyer's side signs after the offer must still find the offer open: the user's L2 in Immediate mode, valid 15 minutes (§7), and the agent's L3b in Autonomous mode, valid up to an hour (§7), each with the 300 seconds of clock skew §5.7 recommends. So an offer stays open at least 1,200 seconds for Immediate and 3,900 seconds for Autonomous `[I]`.
9. No constraint type carries H: Verifiable Intent rejects open mandates with unknown constraint types.
