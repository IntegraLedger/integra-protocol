**LCP profile `acp/checkout/session-id`: the ATR hash as the ACP checkout session id.** This profile targets ACP 2026-04-17.
1. The merchant sets the checkout session's `id` to H, the SHA-256 of the ATR's exact bytes, as `0x` lowercase hex, and sets `metadata.legal_context` = `{"type":"sha256","value":H,"legal_context_url":L}`, where L is an `https` URL that serves those bytes.
2. The agent fetches L, hashes the bytes received, compares the result with the session `id` as 32 decoded bytes, and does not pay on a mismatch.
3. On a handler that requires `delegate_payment`, the agent's `allowance.checkout_session_id` is that `id`, so the vault token it signs for names H.
4. One session binds one ATR. A change to the terms the ATR records needs a new session.
5. On `acp/checkout/delegated` the allowance's `checkout_session_id` carries H as a link, not as a field the payer reliably signs. ACP has the agent sign the `delegate_payment` request with a detached `Signature`, a MUST in one section of its delegate-payment RFC (`rfcs/rfc.delegate_payment.md:38` at ACP `7fdd78d`) and RECOMMENDED in another (`:53`); the PSP SHOULD verify it (`:275`); and the token is held to the allowance's reason, maximum amount, currency and expiry (`:64`), not to its session. So the pairing's `carrier.signed` is null and its `claims` false: `bound` reads H from the allowance as the checkout's link, which shows neither that the payer signed H nor which payment was made under it.
6. On `acp/checkout/undelegated` nothing the payer presents names H. The seller names the charge by its own reference for it, as `card-seller-reference.md` rule 5 states: `reference` takes `{"charge":R}`, R of 1 to 255 visible ASCII characters, with the handler option the checkout was offered on, `{"requires_delegate_payment":false}`, and gives `{"charge":R}`, the checkout being the session whose `id` is H. A presentation that is not an object whose `charge` has that form is `acp/charge-reference-malformed`; then an option whose `requires_delegate_payment` is not `false` is `acp/option-malformed`. Nothing the charge moved is compared with the option.
