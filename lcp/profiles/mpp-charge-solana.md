**LCP profile `mpp/charge/solana` and `mpp/charge/solana/unsponsored`: the ATR hash as the Solana charge's Memo instruction.** Rules 1–3 and 5 of `mpp/charge` apply to the challenge.

1. The request's `externalId` is `lcp:sha256:0x` + 64 lowercase hex of H, 77 UTF-8 bytes. A request whose `externalId` is present with another value is refused `svm/carrier-occupied`: the scheme has one memo, and a seller's own reference belongs in the ATR's content.
2. MPP says the client SHOULD, not MUST, write the memo; this profile makes it required. The client writes `externalId` as a Memo Program instruction (`MemoSq4gqABAXKb96qnH8TysNcWxMyWCqXgDLGmfcHr` or `Memo4c2pN8afCj432Lb7RMVKi9PbQnnW7ewFFaV3oAH`) of the transaction it signs.
3. Among the transaction's top-level Memo instructions, exactly one has data that parses as an LCP string. It is spelled exactly as rule 1 gives, in lowercase hex, else `svm/carrier-not-canonical`, and it equals the echoed request's `externalId`. Other Memo instructions, such as split labels, are not read.
4. `type="bundle"`: the carrier is read from the last transaction, which contains the confidential `Transfer`. MPP: *"A server that does include a memo MUST treat the resulting order-id linkage as an explicit privacy trade-off, and MUST verify any memo present in the bundle matches the value it issued."*
5. `type="signature"`: the client has already broadcast, so the server reads the landed transaction and applies rule 3 to it. The money has moved before the check, so a failed check is reported to the seller, never a refusal.
6. What a record of this pairing proves: the payer's own signed act carries this ATR's hash: a Solana transaction the buyer's account signed, whose one LCP-form Memo instruction is the hash's LCP string, final at `finalized` with no error. It paid each transfer it made from the buyer's account, recorded with its mint or lamports, amount and recipient, one of zero included, the recipient being the owner the transaction's token balances name; as a payment, one of them reached an account the option's payee owns. The memo is in the transaction's instruction data on chain. It compares no amount, mint or time with the ATR's terms.
7. A challenge whose `methodDetails.feePayer` is `true`, with the fee payer's key in `feePayerKey`, is `mpp/charge/solana`. The stock client refuses to broadcast under it from `@solana/mpp` 0.6.0 (`src/client/Charge.ts:79-83` at 0.7.0), so it admits the `transaction` and `bundle` credentials, which the server or its settler co-signs as fee payer and submits; a `signature` credential, which a client before 0.6.0 set to broadcast pushes, is a payment that has already moved, read under rule 5. Every challenge of `mpp/charge/solana` sets `feePayer: true`. Any other challenge, `feePayer` absent or `false`, is `mpp/charge/solana/unsponsored`: its payer can broadcast, so it is never an agreement option. `pairingsOf` names one of the two for each challenge.
