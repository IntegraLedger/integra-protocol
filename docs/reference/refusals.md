# Refusal codes

Every function in this package whose type carries a refusal answers a failure with a value, `{ refused: true, code }`,
and every code is `<namespace>/<reason>` ([Refusals](../concepts/refusals.md)). A `recover` given a ref or reader that
is not an object, or a ref whose transaction id is not in its rail's form, refuses with nothing read, with the code it
gives a reader for another network.
The writers whose type carries no refusal, such as `toLcpString`, throw a
`TypeError` on an argument outside their type instead ([What throws](../concepts/refusals.md#what-throws)).
A link is an absolute URL, on this page, when the WHATWG URL Standard's basic URL parser reads it with no base, as the
package's own copy of that parser reads it ([The link](../concepts/atr-hash.md#the-link)), on every runtime alike.
This page lists all 561 codes the package can return, by namespace. CI checks that every `refusal(…)` call in the
source passes its code as a string literal, that this page lists exactly those codes, each once, and that this total
and the namespace counts below match its rows.

A meaning that begins **Read to repeat.** is that of a code `readToRepeat` answers true for: the answer rests on a read
of the rail that may answer differently later, with nothing the caller must change, so the caller asks again later
([Reads to repeat](../concepts/refusals.md#reads-to-repeat)). No other code is a read to repeat: `wrong-reader` and
`read-first` codes are calls the caller changes. `node scripts/docs-reference.mjs` writes the marks from the set
`readToRepeat` answers from, and CI checks that they match it.

## core

The core: `assemble` and the JSON checks under it.

| Code | Meaning |
|---|---|
| `core/binding-not-json` | `assemble` refuses an `id` that is not a string, or a binding value that is not serialisable JSON with safe-integer numbers and at most 64 levels of nesting. |
| `core/content-not-json` | `assemble` refuses a `content` that is not an array, or party content that is not a `Uint8Array` holding exactly one JSON value in which no object repeats a member name (after escape decoding), no number overflows a double and no integer lies beyond 2^53 - 1 either way, and `canonicalJson` and `digestJson` refuse a value that is not JSON (deeper than 64 levels, a non-finite number, a string with an unpaired surrogate, or a non-JSON type). |
| `core/slot-duplicate` | `assemble` refuses two party slots with the same name. |
| `core/slot-name` | `assemble` refuses a binding or a party slot that is not an array of two, or a binding slot or party slot name that is not a string of 1 to 64 characters from `A-Z`, `a-z`, `0-9`, `.`, `_` and `-` starting with a letter or digit. |
| `core/slot-reserved` | `assemble` refuses a slot named `atrVersion` or `id`, or a party slot that reuses the binding slot's name. |
| `core/too-large` | `assemble` refuses a `maxBytes` limit that is not a non-negative safe integer, more than 64 party slots, or an ATR whose bytes would exceed the limit (at most 1 MiB). |

## spend-permissions

The Spend Permission exchange (`@integraledger/lcp/spend-permissions`).

| Code | Meaning |
|---|---|
| `spend-permissions/account-is-spender` | `build` is given an `account`, or `checkReturn` a return whose permission's `account`, that is the permission's `spender`, the option's payee, whose approval proves no agreement. |
| `spend-permissions/choice-malformed` | `build` is given a choice that is not an object or whose `account` is not an address, or `checkReturn` a clock that is not a non-negative safe integer. |
| `spend-permissions/ended` | `checkReturn` finds that the permission's `end` is not later than the clock it is given. |
| `spend-permissions/header-malformed` | A `Spend-Permission` header's value, or a return given to `encodeSpendPermissionHeader`, `checkReturn`, `approvedIn`, `bound`, `broadcaster` or `reference`, is not base64url without padding in its canonical form of at most 65,536 bytes of well-formed UTF-8 of one JSON object, at most 64 levels deep, holding `network`, `manager`, the whole `permission` in the exchange's wire form and exactly one of `signature` and `transaction` (a 32-byte hash), and no other member, or carries a `refused` member; or `approvedIn` is given no transaction to read on the signature route; or `permissionHash` is given a permission, network or manager not in that form. |
| `spend-permissions/legal-context-malformed` | `advertise` refuses an invalid ATR hash or a link over 2048 characters; `read`, `build`, `checkReturn`, `reference` and `unplaced` refuse an offer with no `legalContext`, or one that is not `{type: "sha256", value, legalContextUrl}` with a 32-byte hash and an `https` link of at most 2048 characters. |
| `spend-permissions/link-not-https` | The link given to `advertise` is not an `https` link, or the offer's `legalContextUrl` is an absolute URL whose scheme is not `https`. |
| `spend-permissions/not-approved` | `approvedIn` finds that the transaction it reads, whose receipt it holds, has no `status` 1 with the SpendPermissionManager's `SpendPermissionApproved` for the permission's hash and the permission whole, and that the manager does not read the permission revoked in the state after its block. |
| `spend-permissions/not-bound` | The permission's `salt` is not H: an offer whose `salt` differs from its `legalContext.value`, an offer given to `advertise` whose `salt` is not the H given, a `build` given an H that is not the offer's, or a `bound` or `reference` given an H the return's `salt` is not; or a return whose `network`, `manager` or offered permission members differ from the offer `checkReturn` or `reference` holds it to. |
| `spend-permissions/option-malformed` | An offer, or the `402` body that holds it, is not in the exchange's form: not an object, a member it does not name, a permission not in the wire form or holding `account`, `accepts` not a non-empty array of distinct routes, a body over 65,536 bytes as JSON or a body `error` that is not one of the exchange's codes; or the SpendPermissionManager refuses the permission: a zero `token` or `spender`, a zero `period` or `allowance`, or a `start` not before `end`; or `unplaced` is given an offer that carries a `refused` member; or `issuedDigest` is given a value that is none of an offer as `advertise` takes it, an offer as `read` takes it and a return as the `Spend-Permission` header carries it. |
| `spend-permissions/revoked` | `approvedIn` finds that the transaction it reads holds no approval of the permission and that the SpendPermissionManager reads the permission revoked in the state after its block. |
| `spend-permissions/route-not-accepted` | `checkReturn` finds that the return takes a route, `signature` or `transaction`, that the offer's `accepts` does not name. |
| `spend-permissions/signature-invalid` | A return's `signature` is not `0x` and 1 to 8192 bytes of hex. The SpendPermissionManager verifies the signature itself when `approveWithSignature` is submitted. |
